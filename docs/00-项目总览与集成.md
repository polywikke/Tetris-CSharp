## 3. 依赖与数据流

依赖方向（只允许这样引用，反向 review 直接打回）：

```
Tetris.App ──→ Tetris.Persistence ──→ Tetris.Core
     └──────────────────────────────→ Tetris.Core
Tetris.AI  ─────────────────────────→ Tetris.Core
tests      ─────────────────────────→ Tetris.Core / Tetris.AI
```

运行时一帧发生了什么：

```
每 1/60 秒：
   键盘 ──KeyMap──▶ GameCommand ──▶ IGameEngine.Apply()      (玩家)
   AI   ──NextCommand───────────▶ GameCommand ──▶ 同上        (自动玩家)
                                            │
                                            ▼
                                      IGameEngine.Tick()     (重力、锁定、消行)
                                            │
                                            ▼
                                        GameState ──只读──▶ BoardView / HUD
                                            ▲
                                            │ Clone()
                              C 的 AI 用 IGameRules 在副本上推演落点
```

**关键点：**

- 界面永远不修改 `GameState`，它只读；
- AI 永远不修改真实状态，它克隆后再推演；
- 所有"会改变游戏"的动作都必须经过 `IGameEngine.Apply` 或 `Tick`。

## 4. 接口地图（谁实现、谁调用）

| 接口 | 实现者 | 调用者 | 用途 |
|---|---|---|---|
| `IGameRules` | A | A（引擎内部）、C（AI 推演） | 碰撞、下落距离、移动、旋转、锁定+消行 |
| `IGameEngine` | A | B | 开局、接受命令、推进一帧、读状态 |
| `IHighScoreStore` | B | B、C（测试里可造假实现） | 读/写最高分，失败不抛异常 |
| `IPlayerAgent` | C | B | 每帧产出一个 `GameCommand` |
| `IPlayerAgentDebug` | C（可选） | B（可选） | 暴露候选落点与评估明细，用于画热力图 |
| `IRandomSource` | A（已提供） | A | 7-bag 洗牌，保证同种子可重现 |
| `IScoreRule` | A（已提供） | A | 一次消 k 行得 100×k 分 |

**共享数据**：`GameState`、`Tetromino`、`GameCommand`、`GameConfig`、`PieceShape`、`AgentCandidate`。
坐标约定 `[x, y]`（x 列、y 行、y=0 在顶部），方块位置是 **4×4 包围盒左上角**。

## 5. 怎么拼起来：四个集成点

按依赖顺序做，**前一个没通不要动下一个**。

### 集成点 ①：A 交规则 → C 接真规则

- 前置：`StandardGameRules` 的五个方法全部实现完（即 A 的交付 ③ 完成）；
- C 把测试里的假规则换成真规则，AI 开始能"看见"棋盘；
- 验收：`dotnet test` 里规则相关用例由红转绿。

### 集成点 ②：A 交引擎 → 自己先跑通

- 前置：`GameEngine` 能开局、下落、锁定、消行、结束（即 A 的交付 ④ 完成）；
- A 用固定种子跑 5000 帧不崩，`dotnet test` 全绿；
- 验收：A 在本机临时把 `AppBootstrap` 换成真引擎，确认界面能真的玩（正式接线由 B 在集成点 ③ 做）。

### 集成点 ③：B 接线 → 整局可玩（最关键的一次集成）

B 只改 `src/Tetris.App/AppBootstrap.cs` 这一个文件（暴露规则工厂 + 换成真引擎），对应 B 的交付 ⑤：

```csharp
using Tetris.Core.Engine;
using Tetris.Core.Rules;

public static IGameRules CreateRules() => new StandardGameRules();

public static IGameEngine CreateEngine(int seed) =>
    new GameEngine(GameConfig.Default, CreateRules(), new XorShiftRandomSource(seed));
```

同时删掉文件顶部的 `using Tetris.Core.Testing;`。

验收：`dotnet run --project src/Tetris.App` 能完整玩一局（下落、旋转、消行、升级、暂停、结束、存高分）。
**从这一步开始，三个人的代码第一次真正合在一起，谁坏了要当天修。**

### 集成点 ④：AI 接进界面（B 接线、C 提供 agent）

B 的改动（三处，对应 B 的交付 ⑥）：

1. `Tetris.App.csproj` 加一行引用：
   ```xml
   <ProjectReference Include="..\Tetris.AI\Tetris.AI.csproj" />
   ```
2. `MainForm` 加 F3 开关（AI 与引擎共用 `AppBootstrap.CreateRules()` 返回的同一个规则实例）：
   ```csharp
   private IPlayerAgent? _agent;

   private void ToggleAgent()
   {
       _agent = _agent is null
           ? new HeuristicAgent(_engine.State.Config, AppBootstrap.CreateRules())
           : null;
       _agent?.Reset();
   }

   // OnFrame 里、Tick 之前：
   if (_agent is not null) _engine.Apply(_agent.NextCommand(_engine.State));
   ```
3. 画 AI 的决策可视化（可选但强烈建议）：把 `_agent as IPlayerAgentDebug` 的 `Candidates` / `Chosen` 交给 `BoardView` 画热力图。

验收：按 F3 后 AI 自己玩；再按 F3 立刻交回玩家，当前方块不跳变。

## 7. 协作规则

- **分支**：`feat/core`、`feat/ui`、`feat/ai`，完成后合并到 `main`。
- **提交**：每完成一个能验证的小步就提交一次，信息写成 `feat(core): 实现 SRS 踢墙` 这种格式。
  老师要求 ≥12 次、≥4 个不同日期，**不接受最后一天一次性提交**——所以别攒着一起提交。
- **合并条件**：`dotnet build` 0 错误 + 自己的测试全绿 + 没动别人目录。
- **改接口**：先在群里说明影响，A 同意后当天改完所有调用点，全员重新 build。
  **集成点 ③ 之后接口冻结**，只能加不能改。
- **卡住超过 1 小时**：在群里贴"文件:行号 + 报错 + 你试过什么"，不要闷头硬扛。
